# Auto Download Converter

A Microsoft Edge / Chromium extension that watches your downloads and automatically
converts them to a format you choose, based on rules you control.

```
download file  →  detect type  →  match rule  →  convert  →  save  →  keep/delete original
```

Everything runs **locally**. Files are never uploaded anywhere. See [PRIVACY.md](PRIVACY.md).

## What's actually inside this repository

This project has two parts that work together:

| Part | What it does | Requires install? |
|---|---|---|
| **`extension/`** | The Edge/Chrome extension itself: watches downloads, matches rules, runs the queue, shows the UI. Also contains the built-in converters for text/data/image formats (pure JS/TS, no external engine). | Load unpacked, or package for the Web Store. |
| **`native-host/`** | A small local helper program the extension talks to over Chrome's Native Messaging protocol. Required for **any** conversion to actually read/write files (Chromium extensions have no general local filesystem API - see [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)), and it's what invokes FFmpeg/Pandoc/LibreOffice for audio/video/document conversions. | Yes - see [docs/NATIVE_HOST_INSTALL.md](docs/NATIVE_HOST_INSTALL.md). |

## Quick start

```bash
npm install          # installs deps for both extension/ and native-host/ (npm workspaces)
npm run build         # builds both
npm test              # runs the real test suites (see "Testing" below)
```

Then:
1. Install the native host: follow [docs/NATIVE_HOST_INSTALL.md](docs/NATIVE_HOST_INSTALL.md).
2. Load the extension: follow [docs/INSTALL.md](docs/INSTALL.md).
3. Open the extension's Options page → **Rules** → create a rule (e.g. `.txt → pdf`).
4. Download a matching file. It should convert automatically - check **Queue** / **History**.

## What conversions are supported

See [docs/CAPABILITY_MATRIX.md](docs/CAPABILITY_MATRIX.md) for the full, current list and exactly
which engine each one needs. The short version:

- **No install needed** (built into the extension): TXT/MD/CSV/JSON/XML ↔ PDF/HTML/DOCX/RTF/XLSX/TXT/MD/CSV,
  and image conversions (JPG/PNG/WEBP/BMP/GIF, plus images → PDF).
- **Needs FFmpeg** (via the native host): MP3/WAV/OGG/M4A/FLAC conversions, and MP4/MOV/MKV/WEBM
  conversions including audio extraction.
- **Needs LibreOffice and/or Pandoc** (via the native host): DOCX/RTF/ODT/HTML → PDF, and other
  Office-document conversions.

The extension's **Options → Engines** page shows exactly what's detected on your machine and what
each unsupported conversion is missing. Nothing is ever silently faked - if a conversion can't run,
the job is marked **Failed** with a real reason, never a fake "Completed".

## Project structure

```
auto-download-converter/
├── extension/            Manifest V3 extension (TypeScript)
│   ├── src/
│   │   ├── background/     service worker: download watcher, queue runner, native-messaging client
│   │   ├── converters/     conversion registry + browser-native converters (PDF/DOCX/image/CSV/JSON/XML/MD writers)
│   │   ├── rules/          rule matching + filename templating
│   │   ├── queue/          job/queue types + orchestration logic
│   │   ├── storage/        typed wrappers over chrome.storage.local
│   │   ├── popup/          toolbar popup UI
│   │   └── options/        full settings UI (Dashboard/Rules/Queue/History/Engines/Settings)
│   ├── tests/               real Vitest tests (127+ cases)
│   └── build.mjs            esbuild bundler → extension/dist/ (load this in the browser)
├── native-host/           Native messaging host (Node.js/TypeScript)
│   ├── src/
│   │   ├── engines/         ffmpeg/pandoc/libreoffice detection + invocation
│   │   ├── convert/         conversion orchestration, atomic writes, file I/O bridge
│   │   └── security/        path traversal prevention, filename sanitization, output validation
│   ├── tests/                real integration tests against actually-installed ffmpeg/pandoc/soffice
│   └── installers/           per-OS install/uninstall scripts + native messaging manifest template
├── tests/fixtures/         real sample files (generated by generate.sh) used by both test suites
├── docs/                   architecture, install, troubleshooting, capability matrix
└── PRIVACY.md
```

## Testing

Both test suites use **real files and real engines**, not mocks-of-everything:

```bash
npm run test:native-host   # spawns real ffmpeg/pandoc/soffice against real generated fixtures
npm run test:extension     # PDF/DOCX/XLSX/RTF output independently validated by pdfinfo/pypdf/
                            # python-docx/openpyxl/LibreOffice; rule engine, queue, storage,
                            # native-messaging client tested with dependency-injected fakes
```

See [docs/TESTING.md](docs/TESTING.md) for exactly what was verified, how, and what could **not**
be verified in this development environment (there was no real Chromium/Edge browser available to
run the extension in end-to-end - see that doc for the honest breakdown).
